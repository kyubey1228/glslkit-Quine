# 自分を描くRubyは、どうやって自分を覚えているのか — OUROBOROSのQuineを紐解く①

Rubyのコードが輪の形に並び、そのRubyを実行すると、少し形の違う輪が出力される。これを繰り返すと、24回目で最初のコードへ戻る。

そんな周期Quine「OUROBOROS」を作りました。

[公開作品はこちら](https://glslkit-quine.lolipop-now.app/)です。

作品では、そのコードをWebGLで描き、描画したピクセルからRubyを復元して次の世代を実行しています。いくつかの仕組みが重なっていますが、今回はその土台となる「自分のコードを再生成する仕組み」に絞って解説します。

## Quineとは

Quineは、自分自身のソースコードを出力するプログラムです。

たとえば、次のように実行したとします。

```sh
ruby quine.rb > output.rb
```

このとき、`quine.rb` と `output.rb` の内容が一致します。一般的なQuineでは、自分のソースファイルを読み込まずにこれを実現します。

難しいのは、出力する処理もソースコードの一部であることです。

```ruby
puts "Hello"
```

これは `Hello` を出力しますが、`puts "Hello"` というソース全体は出力しません。その全体を文字列に入れると、今度は文字列を囲む引用符や、それを出力する処理も再現する必要が出てきます。

この問題を解くために、コードを「実行する処理」と「その処理を表す文字列」の両方として使います。

## コードを文字列として持ち、実行する

Rubyでは、`eval` に文字列を渡すと、その内容をRubyとして実行できます。

```ruby
code = 'puts "Hello"'
eval code
```

文字列を変数に保存する操作と、その文字列の実行は、一つの式にもできます。

```ruby
eval(code = 'puts "Hello"')
```

これを使うと、実行されるコードの中から、そのコード自身を保存した変数へアクセスできます。

OUROBOROSでは、コード本体を保持する変数に `$s` を使っています。

```ruby
eval($s = '...')
```

ただし、`$s` に入っているのは、この行全体ではありません。引用符の内側にあるコード本体です。

そこで、本体の前後に `eval($s = ...)` に相当する外枠を付ければ、ソース全体を再構成できます。

この考え方と、次に説明する文字の配置には、[「Quineから始めるRuby超絶技巧プログラミング入門」](https://qiita.com/wataru86/items/adfa71048a206ffe6ffa)が参考になります。

## 輪の形に並べても実行できる理由

普通のRubyコードは、好きな位置で文字を分割できません。

```ruby
pu
ts "Hello"
```

これを `puts "Hello"` として実行することはできません。

ところが、Rubyの `%w` 記法を使うと、空白や改行で区切った文字列の配列を作れます。

```ruby
%w!pu ts!
# => ["pu", "ts"]
```

これを空の文字列で連結すると、分割前の文字列に戻ります。

```ruby
%w!pu ts!*""
# => "puts"
```

`*""` は、ここでは配列の要素を空文字列で連結する操作です。`.join` と同じ役割を持ちます。

`eval` と組み合わせれば、次のコードも実行できます。

```ruby
eval(%w!
  pu
     ts
       "Hello"
!*"")
```

実行時には、内側が次の文字列になります。

```ruby
puts"Hello"
```

つまり、**紙面上での文字の配置と、実行するコードを切り離せます。**

文字を輪の形に並べても、`%w` と連結によってコード本体へ戻せるわけです。ただし、本体に必要な空白まで失われるため、文字列中の空白などは別の表現にする必要があります。また、この自由な配置ができるのは `%w` の内側です。

## 小さなQuineで確かめる

OUROBOROSと同じ外枠を使った、小さなQuineを見てみます。

次の一行を、末尾の改行も含めて `quine.rb` に保存してください。

```ruby
eval$s=%w!print("eval$s=%w"+33.chr+$s+33.chr+"*"+34.chr*2+10.chr)!*""
```

長く見えますが、出力しているものは三つだけです。

| 部分 | 出力する内容 |
|---|---|
| `"eval$s=%w"+33.chr` | 外枠の先頭 `eval$s=%w!` |
| `$s` | 実行中のコード本体 |
| `33.chr+"*"+34.chr*2+10.chr` | 外枠の末尾 `!*""` と改行 |

`33.chr` は `!`、`34.chr` は二重引用符、`10.chr` は改行です。

`!` を文字コードから作るのは、`%w! ... !` の中に区切り文字の `!` を直接書かないためです。

このプログラムは、次の順序で動きます。

1. `%w! ... !*""` からコード本体を作る。
2. 本体を `$s` に保存し、`eval` で実行する。
3. 本体が、自分自身である `$s` の前後に外枠を付けて出力する。

これで、最初のソース全体が再現されます。

```sh
ruby quine.rb > output.rb
diff quine.rb output.rb
```

差分が出なければ成功です。この例は、末尾の改行を含めた完全一致を確認しています。

## OUROBOROSは「配置する処理」も自分の中に持つ

小さなQuineでは、`$s` をそのまま出力しました。

OUROBOROSでは、出力する前に `$s` の文字を輪の形へ配置します。配置を担当するのが、実装中の `e` という関数です。

役割を簡略化すると、次のようになります。これは説明用で、そのまま動くコードではありません。

```ruby
e = ->(generation) {
  # $s の文字を取り出す
  # generation に応じた輪の形を計算する
  # 輪の内側へ文字を順番に配置する
  # 世代番号と eval の外枠を付けて返す
}
```

ここで大切なのは、**この `e` の定義も `$s` に含まれている**ことです。

次の世代として出力されたRubyにも、同じ配置処理が入っています。そのRubyを実行すれば、さらに次の世代を作れます。

出力されるのは、見た目を整えたコードであり、次のコードを生成できるプログラムでもあります。

輪を埋める途中で本体の文字を使い切った場合、残りの場所には `#` を置きます。本体の末尾からコメントになるため、余った場所を埋めても実行する処理を増やさずに済みます。

## なぜ一回で同じコードに戻らないのか

通常のQuineは、一回の実行で同じソースへ戻ります。

OUROBOROSでは、ソースの先頭に世代番号を持たせています。

```ruby
n=0x00;eval$s=%w!
```

最初の世代は `0x00`、つまり `0` です。そして通常実行では、次の式で次世代のソースを出力します。

```ruby
print(e.call((n+1)%24))
```

`n` を一つ進め、`24` で割った余りを次の世代番号にします。

```text
0 → 1 → 2 → … → 23 → 0
```

配置処理は世代番号から輪の形を計算するので、番号が変わるとソースの形も変わります。

24回後には番号が `0` に戻り、同じ本体から同じ配置を再生成します。その結果、ソース全体が最初の状態へ戻ります。

今回、生成済みのRubyを実行して、24世代がすべて異なることと、24回後に最初のソースへ全バイト一致で戻ることを確認しました。

## 最初に作る処理と、次を生む処理

リポジトリには `build.rb` があります。これは最初のRubyやシェーダーを作るための生成器です。

一方、完成した `ouroboros.rb` には、次の世代を作る処理がすでに入っています。

```sh
ruby public/ouroboros.rb > next.rb
ruby next.rb > after.rb
```

この世代交代に `build.rb` は必要ありません。

ビルド時にはテンプレートなどのファイルを読みますが、生成されたRubyが次のRubyを出力するときには、自分のソースファイルを読みません。再生成に必要なコード本体と配置処理を、自分の中に持っているからです。
